# Podobne projekty: orkiestracja agentów kodujących

Sprawdzono **2026-10-25**. Cel porównania: lokalny orkiestrator Python uruchamiający Claude Code i Codex dla repozytorium Rust w kolejności: implementacja → deterministyczne gates → dwie niezależne recenzje → triage ustaleń → poprawki z limitem iteracji. ## Wniosek dla MVP

**Zbudować mały własny orkiestrator Python, bez frameworka agentowego.** Żaden z pięciu nie realizuje dokładnie docelowego kontraktu przy zachowaniu kontroli nad `cargo` i dwoma niezależnymi procesami recenzującymi. Ralphex jest najlepszą referencją dla etapów, limitów i wykrywania zastoju; ralph-gold dla uruchamiania CLI, trwałego stanu i „receipts”; Superpowers dla rozdzielenia implementera, recenzentów i triage. Aider i SWE-agent nie powinny być główną zależnością MVP.

Minimalny kontrakt: uruchamiać CLI przez `subprocess` bez powłoki, z ustalonym katalogiem i limitem czasu; zapisywać kod wyjścia oraz surowe logi; wykonywać konfigurowalne `cargo fmt --check`, `cargo clippy` i `cargo test` jako **twarde gates**; dać obu recenzentom ten sam zamrożony diff i niezależne konteksty; parsować ich raporty do jednego schematu ustaleń; deduplikować i oznaczać `potwierdzone / odrzucone / niepewne` z uzasadnieniem; poprawiać wyłącznie potwierdzone ustalenia; po poprawce ponowić gates i recenzję w skończonym limicie rund. Wynik końcowy powinien jawnie odróżniać `sukces`, `porażka gate`, `nierozstrzygnięte ustalenia` i `limit wyczerpany`. Integrację Rust zapewniają komendy gates, nie osobny agentowy framework.

**Granice weryfikacji:** daty push pochodzą z metadanych repozytoriów GitHub i świadczą o aktywności repo, nie o jakości lub częstotliwości stabilnych wydań. Deklaracje README/FAQ i obecność CI nie są testem integracyjnym na każdym systemie. Szczegóły flag i formatów wyjścia Claude Code/Codex trzeba sprawdzić bezpośrednio w ich aktualnych oficjalnych CLI przed implementacją adapterów. [OpenHands Software Agent SDK](https://github.com/OpenHands/software-agent-sdk) pominięto jako głównego kandydata: oferuje Python/TypeScript/REST API do budowy **własnego** agenta, co rozszerza zakres projektu zamiast sterować obecnymi CLI.
