# Task-file input implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Track checkboxes below.

**Goal:** Support `--task-file PATH` and `--task-file -` for plan/run while preserving positional task input.
**Architecture:** Resolve one input source at the CLI boundary into the existing task string. Providers, stages and saved task/prompt semantics remain unchanged.
**Tech Stack:** Python 3.11+ standard library, unittest fixture providers, Ruff/reviewdog.
**Spec:** The user's explicit request in this conversation; concrete input contract below.

## Input contract

- Exactly one positional task or `--task-file` is required for plan and run. Other commands do not gain this option.
- Missing/both sources are argument errors (legacy parser behavior; machine exit 2 / invalid_arguments). Validate selection before reading either source.
- File paths are relative to the caller, consistent with requirements/config paths. Only the exact value `-` means stdin; `./-` can name an actual file.
- Read once, as UTF-8 bytes where available; support text-only stdin in embedded use. Do not close or reconfigure caller stdin. Preserve whitespace, CRLF/newlines, Unicode and trailing newline in the task string; no interpolation or trimming.
- New file/stdin inputs reject empty or whitespace-only contents and invalid UTF-8 with invalid_arguments. Filesystem/read OSError remains io_error. Interruption remains exit 130.
- Existing positional behavior stays intact, including literal text after `--`; do not opportunistically change legacy empty-plan behavior. `run` retains its existing nonempty-task validation.
- Read the task before Workflow construction so input errors cannot create run artifacts, acquire a project lock or invoke providers. Do not add task provenance fields, limits, new engine arguments or new commands.
- `--task-file` supplies task text, not acceptance requirements. Plan and run must use identical resolved task/requirements/config inputs for a comparable plan.

## Review focus

- UTF-8 stdin must not depend on a locale-specific TextIOWrapper decoder; tests cover redirected binary stdin.
- Conflicting input and help must not consume stdin; a file named `-` must remain usable.
- File contents containing quotes, shell metacharacters or `--json` must remain literal task text.
- Long multiline text must reach routing and saved workflow state intact without a long argv entry.
- Read/decode errors and interruption must preserve JSON/legacy error behavior and cause no provider/run side effects.
