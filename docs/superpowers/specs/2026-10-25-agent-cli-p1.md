# Agent-facing CLI P1 scope

The user approved implementing the three P1 recommendations from the preceding
repository analysis, in this order: observable/cancellable runs, a versioned
machine CLI contract, and operator help/documentation/skill. This document records
that approved scope; it does not request another approval.

## Required behavior

1. Announce the run directory before expensive work. Preserve the final stdout
   JSON and keep progress on stderr. Expose the current role/check and heartbeat
   freshness while a run is active. Handle POSIX SIGTERM through the existing
   interruption, child cleanup, log preservation and lock-release paths.
2. Add an opt-in machine format covering all commands, parse errors and exceptions,
   with a schema version, command result, stable error code and safe next action.
   Keep existing default output/exit semantics, including status returning zero
   for a successful read and plan returning zero when requirements are still needed.
3. Explain all commands and relevant options. Give an executable first-run example
   which creates requirements first, an operator recovery procedure, and a short
   optional skill for the calling Claude Code/Codex agent, separate from backend
   role skills and repository-maintainer instructions.

## Constraints

- Python 3.11+, runtime stdlib only; no paid provider sessions.
- Keep stage order, both independent reviews, frozen-source checks, strict response
  validation, full audit evidence, and explicit apply. Never change models silently.
- Retain unknown usage as unknown. Heartbeat proves supervisor activity only.
- Preserve default CLI output and existing 0/1/2/130 exit semantics; additive progress
  metadata and the initial stderr announcement are compatible extensions.
- Do not implement resume, automatic stale-lock removal, provider retry redesign,
  apply preview, Codex MCP, or an SDK migration in this change.
- SIGKILL/crashes remain outside graceful cleanup guarantees. Do not claim a stale
  heartbeat proves process death or authorizes deletion of the lock.

## Design decisions

Use a small lifecycle module for scoped signal handling and advisory live progress.
Write heartbeat metadata separately from authoritative state.json so a background
writer cannot race acceptance/audit state. Keep terminal state authoritative.
Use opt-in --json for a versioned envelope; default output remains unchanged.
Use optional --events-jsonl on run for machine-readable lifecycle events on stderr.
Ship an instruction-only operator skill as package data; installation is explicit,
uses real files, and never modifies user-level agent configuration automatically.
